# Notes for Claude Code sessions on this repository

- **Releases are the update channel.** The owner tests through the launcher's auto-update, which installs only GitHub releases. `.github/workflows/release.yml` publishes one whenever a push (any branch) changes `level.ix.version` in `mods/infinite_expansion/custom_scripts/ix/core/bootstrap.gsc`. So every push that changes the mod or the setup must raise that version (the last number for fixes and steps: 0.14.1, 0.14.2 …) and add a `### X.Y.Z: <title> (<date>)` heading to `CHANGELOG.md`, whose section becomes the release notes. Also update the version in the README status line and init line, `PLAYTEST_CHECKLIST.md` (title, S1) and `TESTING.md` R-S1. Documentation-only or test-only pushes keep the version. After pushing, check that the release exists and that its zip matches the commit (`TESTING.md` V164 shows how).
- Before every push: `python3 tools/check.py` and `python3 -m unittest discover -s tools/tests` must pass (the toolchain: `tools/setup_compilers.sh`; `lua5.1` for the Lua checks).
- Verify every API, field and file format from source (iw7-mod, x64-zt, the decompiled stock scripts in `.toolchain/src/iw7-gsc-dump`) and say where it came from; anything impossible is "BLOCKED — IW LIMITATION". Never ship the game's own art. Every feature can be switched off. Keep the docs listed in `README.md` "Documentation" current.
- **Custom emotes: always ask whether each one loops.** Looping is set per emote when the owner and Claude set it up (the list's `loop` field, later the manifest), never by players in game, and never assumed: ask the owner for every new emote. Known so far: `DanceMoves` (the owner's dance) plays once, no loop.
